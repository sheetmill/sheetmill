# Excel capture jobs: the job format (version 1)

Some of the expected results in the sheetmill packages are captured from Microsoft Excel by a
**job**: a manifest that lists, in order, every operation done to Excel, beside the workbooks it
opens. A job is data, never code: it cannot run a macro, reach the network or name a path outside
its own folder. The manifest committed beside a capture is the complete record of what was done
to Excel to produce it, so anyone can read it and repeat it by hand in Excel, or with a driver of
their own, and compare what they get.

The program that runs jobs and drives Excel is not published. This page and the manifests
committed beside each capture are the record of what it does: every operation it can perform is
described here, and a manifest can ask for nothing else.

This page describes the format: the job folder, the manifest, each operation and its effect in
Excel's terms, the result files, and the facts recorded about the machine a job ran on.

## The job folder

```
<job_id>/
  job.json      the manifest
  files/        the input workbooks and text files, named in the manifest
```

`job_id` is `<package>-<yyyymmdd>-<hhmmss>-<label>` (lowercase letters, digits and hyphens). Input
files are `.xlsx`, `.xltx`, `.csv`, `.tsv` or `.txt`, at most 2,000 files and 2 GiB, with plain
names (letters, digits, `. _ - [ ] '`; no path separators, no reserved device names). Inputs are
generated by the package's own code, which is committed beside the manifest; regenerating them
gives the same files.

**Inputs a job refuses**, so that what Excel does cannot depend on anything but the files: macro
workbooks (`.xlsm`, `.xls`, or any package holding a VBA project), packages with external links,
data connections, query tables or embedded objects, formulas that reach outside the machine or
run code (`WEBSERVICE`, `IMAGE`, `RTD`, `CALL`, `REGISTER`, `EXEC`, `STOCKHISTORY`, `PY`),
references to other workbooks, and DDE forms (a `|` outside a string literal in a formula, in
workbooks and in text files alike). Excel opens every file with macros disabled and with links
not updated.

## The manifest (`job.json`)

```json
{
  "schema": 1,
  "job_id": "xlrecalc-20260101-120000-example",
  "package": "xlrecalc",
  "purpose": "example: open a workbook and save a copy",
  "requires": {"excel_build_min": {"windows": "16.0.19000.0"}},
  "limits": {"job_seconds": 3600, "step_seconds": 600},
  "audit": false,
  "workbooks": [
    {"file": "example.xlsx", "steps": [
      {"op": "open"},
      {"op": "save_as", "name": "example.copy.xlsx", "format": "xlsx"}
    ]}
  ]
}
```

| field | meaning |
|---|---|
| `schema` | the format version: 1 |
| `job_id`, `package`, `purpose` | names; `purpose` is one line of plain text |
| `requires` | optional: `excel_build_min`, the minimum Excel build per platform, as an object with a `windows` entry, a `macos` entry or both (such as `{"windows": "16.0.19000.0", "macos": "16.115"}`), keyed by the names a capture's header gives the operating systems (any other key is refused, and so is a plain string; see "Which machine can run a job"); and `edition`, one of `Microsoft 365`, `Office 2024`, `Office LTSC 2024`, `Office 2021`, `Office LTSC 2021` and `Office 2019` (the job is refused on any other edition, and on a machine whose edition is not known) |
| `limits` | `job_seconds` (default 3,600) and `step_seconds` (default 600); a step past its limit is a hang, recorded and never retried |
| `workbooks` | run in order; each opens one file (or makes a new workbook) and runs its steps; every workbook is closed **without saving** at the end of its steps |
| `on_refused_open` | `record` (default: note the refusal, go on) or `stop` |
| `control` | optional: a workbook opened before and after the others; a file's open or refusal counts only between two controls that opened |
| `needs_person` | `true` when a step waits for a person (below) |
| `audit` | `true` for the stricter settling check of window captures (below) |

A cell range is written as in Excel, with an optional sheet: `Sheet1!A1:C40`, `'My sheet'!B2`;
columns `A:C`, rows `1:3`. Every step may carry an `id` (it names the step's result) and
`seconds` (its own time limit).

## Operations

Excel is started fresh for each job, with macros disabled and alerts off, and quit at the end. In
the table, the Excel terms are those of Excel's object model on Windows (VBA); a note marked
"Mac:" says how Excel for Mac does the same through AppleScript where the two differ.

| op | arguments | what is done in Excel | result |
|---|---|---|---|
| `open` | `alerts`: true turns Excel's alerts (`DisplayAlerts`) on for this open only (default false); `via`: `com` (the default: through Excel's object model) or `shell`; `repair`: `refuse` or `person`; `message` and `expect` for the person forms, as for `person` | `Workbooks.Open` with links not updated. `via: shell` opens the file as a double-click does; `repair: person` lets a person answer Excel's repair dialog | the workbook's name, or **refused** when the open fails |
| `new_workbook` | none | `Workbooks.Add` | the workbook's name |
| `app` | `get`: `version`, `build`, `build_number`, `standard_font`, `standard_font_size`, `calculation` | reads Excel's application settings: `build` is the full build, as in the header's `excel.build` (such as `16.0.19000.20000`; on Windows read from Office's installation, since the object model gives only the version and the build number), `build_number` is `Application.Build` (such as `19000`; Excel for Mac has none, and a job asking for it there is refused) | the values |
| `workbook` | `get`/`set`: `date1904`, `saved` | the workbook's date system and saved flag | the values |
| `calculate` | `kind`: `normal`, `full`, `rebuild` | `Calculate`, `CalculateFull`, `CalculateFullRebuild` (Mac: `calculate`, `calculate full`, `calculate full rebuild`) | none |
| `write` | `range` and one of `values` (rows of values), `formulas`, `formulas2` (rows of formula text), `paste_text` (lines) | sets `Value2`, `Formula` or `Formula2` (the dynamic-array form); `paste_text` pastes the lines as typed text through the clipboard | per cell, whether it took |
| `read` | `range`, `props` from `text`, `value2`, `formula`, `formula2`, `number_format`, `number_format_local`, `column_width`, `row_height`, `width`, `height`, `left`, `top` | reads each property; `text` is what the cell displays at its current width (`Range.Text`, one cell at a time) | a grid per property (values typed, below) |
| `read_format` | `range`, `props` such as `font.color`, `interior.pattern`, `borders.bottom.line_style`, `align.horizontal`; `display` | reads the cell's own format, or with `display: true` the format Excel displays (number-format colors, conditional formats, table styles: `DisplayFormat`) | per cell, each property or its error |
| `copy_text` | `range` | copies the range (`Range.Copy`) and reads the text Excel puts on the clipboard; the clipboard is restored after | the text |
| `set_size` | `columns` with `width` (Excel's character units) or `rows` with `height` (points) | sets column widths or row heights | the sizes Excel reports back |
| `autofit` | `columns` | `AutoFit` on whole columns | the widths after |
| `view` | `sheet`, `zoom` (10 to 400), `select`, `scroll_row`, `scroll_column` | activates the sheet, sets the zoom first, then the selection and the top-left visible cell | the zoom, the visible range and the window's bounds |
| `capture_window` | `name` (a `.png`), `stable` (default true: wait until the window has settled, below; false: one shot at once), `regions` (`tabs`) | a picture of Excel's window, taken once the window has settled (below) | the picture, its size, the pixels per point and how it settled |
| `save_as` | `name`, `format`: `xlsx`, `csv`, `pdf`, `html`, `web_archive` | saves a copy (`SaveAs`; PDF: `ExportAsFixedFormat`); the open workbook takes the copy's name, as in Excel (Mac: `save as`; `web_archive` is Excel for Mac's `HTML file format`, a single web archive file; Excel for Mac has no equivalent of `html`, a page with a folder of files) | the file, kept with the results |
| `person` | `message` (what the person is asked to do), `expect` (what they will see and how to answer it) | nothing: the job waits until the person at the machine says they are done | the person's note |
| `close` | `save`: false | closes the workbook without saving | none |

**Which machine can run a job.** A job runs only on a machine whose Excel can perform every
operation it uses. A job that uses an operation the machine's Excel lacks (on a Mac, `save_as`
with `format: "html"`) is refused before Excel starts, with the operation named. The "Mac:"
notes say how to repeat a step by hand in Excel for Mac; they do not mean that every operation
has been run there.

A job that names `requires.edition` runs only on a machine whose Excel is that edition, and is
refused before Excel starts otherwise. The edition decides which functions Excel has, so a job
whose results depend on a function names the edition it was written for. Office of a given year
and Office LTSC of the same year are different editions. On Windows the edition is read from
Office's installed products (`O365...` is Microsoft 365; a retail product of 2024, 2021 or 2019
is Office of that year, a volume product of 2024 or 2021 is Office LTSC of that year, and any
other product of those years leaves the edition unknown); on a Mac it is part of the machine's
configuration, as Excel > About Excel shows it. A job that names no edition runs on any.

A job that names `requires.excel_build_min` runs only on the platforms it names: each platform
numbers its builds differently, so a minimum is given per platform, never once for both. It is
refused before Excel starts when the machine's `excel.build` is older than its platform's
entry. Both are split at the dots and compared part by part as whole numbers, so the Windows
build `16.0.19000.20000` meets a `windows` minimum of `16.0.19000.0` and not one of
`16.0.19001.0`, and the Mac build `16.115.26110837` meets a `macos` minimum of `16.115` and not
one of `16.116`. A job that names no minimum runs on either platform.

The window is **maximized** before any job that shows it (Excel's own `WindowState = xlMaximized`
on Windows; Excel's `window state maximized` on the Mac), so a job does not size the window, and
the window's geometry is part of the machine's record (below).

**Settling a window capture.** Excel may still be drawing after an operation returns, so a capture
is taken only once the window has held still: shots are taken repeatedly and compared over the row
and column headings and the cells (plus the sheet tabs when the capture names `regions: ["tabs"]`),
and the capture is settled when nothing there has changed for 0.4 s (it fails after 8 s). Each
capture's result records how many shots it took, when the last change came, how long the stillness
lasted, and the longest stillness a later change interrupted; any capture where that came within
0.1 s of the 0.4-s window is named in the job's notes. The job's first capture is shot again 1 s
after settling and must be unchanged. With `audit: true`, every capture is watched for 2 s after
settling and must stay unchanged; audit mode is meant for a suite's first capture, for the first run
after any update of Excel or the operating system, and after a near miss.

**A person step** (`person`, or `open` with `via: shell` or `repair: person`) waits for the person
at the machine; the job declares it in advance (`needs_person: true`), and nothing is sent to Excel
while a dialog of Excel's may be open.

## Results

```
<job_id>/
  result.json   the outcome, the machine's record, and every step's result
  log.txt       the runner's log
  artifacts/    saved copies, PDFs, web pages, window pictures
```

`result.json` holds the job's `status` (`ok`, `refused` with its `problems`, `error`, `timeout`,
`hung`), whether Excel was left clean (every workbook closed unsaved, settings restored, Excel
quit: checked after cleanup), `notes`, and per workbook its open time and each step's status
(`ok`, `refused`, `error`), seconds and result. It also records the SHA-256 of the manifest
(`manifest_sha256`) and of each input file, with its size in bytes (`inputs`, by file name,
computed from the files the job received), and a `header`: the fields a capture's header copies
(below).

**Values** read with `value2` are typed: `{"t": "number", "repr": "0.1"}` (the exact double as its
shortest text), `{"t": "text", "v": "…"}`, `{"t": "bool", "v": true}`, `{"t": "empty"}`, and
`{"t": "error", "v": "#N/A"}`. The value of record is read from a saved copy with the package's
own reader, as for any capture; reads through Excel are secondary.

**A capture's header.** A package copies `result.json`'s `header` whole into its capture's
header. It holds the format version (`format`), the version of the program that ran the job
(`runner_version`), the `job_id`, `manifest_sha256`, `inputs`, and `environment`, the machine's
record:

| field | what |
|---|---|
| `windows` or `macos` | the operating system's version and build, the architecture; the Windows edition, or the Mac's light or dark appearance |
| `office` | on Windows, Office's version, its installed platform, the license product and the update channel |
| `excel` | the version; the full build (`build`, text on both platforms: on Windows the version Office's installation reports, such as `16.0.19000.20000`; on a Mac Excel's bundle version, `CFBundleVersion`, which is the version and the number About Excel shows in parentheses, joined by a dot, such as `16.115.26110837` for what Excel > About Excel shows as `16.115 (26110837)`), and on Windows also Excel's own build number (`build_number`, such as `19000`); the update channel (on a Mac; on Windows it is in `office`), the operating system as Excel reports it, the calculation version, the standard font and size, the decimal and thousands separators and whether the system's are used, the international settings, and the process architecture |
| `edition` | the machine's Excel edition (`found`, one of the editions above, or none when not known) and where it was read (`source`: `office products`, or `edition.txt`, the machine's configuration file) |
| `display`, `geometry` | the screen's size in pixels and its DPI (on the Mac also its points and scale), and Excel's maximized window, each against the values expected for the machine (`geometry`: expected, found, ok) |
| `locale` | the locale name, the separators, the short and long date and time formats, the code pages, the two-digit-year limit, the sort locale and its version |
| `fonts` | each font face the captures use (Calibri, Aptos, Aptos Narrow, Aptos Display, Segoe UI): family, style, the version inside the font and whether it is one of Office's cloud fonts |
| `theme` | Office's theme and the system's light or dark settings |
| `printer` | the default printer's paper size and orientation, which set a PDF's pages |
| `checks`, `audit` | the macro and DDE settings the job required, and the audit flag |

On Windows, the program that runs the job fetches Office's cloud fonts before the first workbook
opens.

The header is chosen field by field, so it carries nothing that identifies the machine: no
user, printer name, path or process number. `result.json` keeps the rest for the person who
ran the job.

## Repeating a job

Read the manifest top to bottom. For each workbook: open the file (alerts off, links not
updated), do each step in Excel as the table says, and close without saving. For a window capture,
maximize Excel's window and wait until the cells have stopped changing. To confirm that you start
from the same files, compare the SHA-256 of each regenerated input with the capture header's
`inputs`. Compare what you get with
the committed capture, field by field, keeping in mind the machine's record: a different Excel
build, display scaling or locale can change what Excel displays.

## What a package commits for a capture

For a capture made by a job, a package commits, beside the generator that writes the inputs and
the measuring code that reads the results: the manifest the job ran, and the capture's rows under
a header copied from the result's `header` (format version, job, the manifest's and inputs'
checksums, the machine's record). By kind of capture:

| kind | example | the manifest's operations | measured from |
|---|---|---|---|
| saved copies | xlrecalc's computed values | `open`, `save_as` xlsx | the saved copy, read by the package's own reader |
| displayed text and widths | xlformat's number formats at set widths | `open`, `set_size` per width, `read` `text` and `column_width`, `copy_text` for the width-less form, `read_format` `font.color` with `display` | the step results |
| window pictures | sheetpeek's fills at zoom 100 and 200 | `open`, `view`, `read` of cell geometry, `read_format` of displayed fills, `capture_window` per zoom and scrolled view | the pictures, by the package's measuring code (the pictures stay out of the repository) |
| text files opened | [xlio](https://github.com/sheetmill/xlio)'s CSV fields | the `control` workbook, `open` of each CSV, `save_as` xlsx | the saved copies |

The manifest names inputs by file name only, and the generator recreates them; the header's
`inputs` lets a reader confirm that the regenerated files are the ones the job opened.

## Versions

- **1** (2026-11-21): the first version. Corrected the same day, before any committed capture
  used it, so that `requires.edition` is checked rather than only recorded, the `app`
  operation's `build` is the full build, and `requires.excel_build_min` gives one minimum per
  platform, keyed `windows` and `macos` (a plain string is refused); manifests keep
  `"schema": 1`.
